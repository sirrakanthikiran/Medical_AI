FHIR converts each fact into a standard resource with the same shape everywhere:

{ "resourceType": "Observation", "subject": { "reference": "Patient/ravi" }, "code": { "coding": [{ "system": "http://loinc.org", "code": "2708-6", "display": "Oxygen saturation" }]}, "effectiveDateTime": "2026-05-10T16:30:00", "valueQuantity": { "value": 94, "unit": "%" } }

Ravi now has a Patient resource, dozens of Observation resources (vitals, labs), Condition resources (diagnoses), and Procedure resources (the surgery) — all using internationally standard codes (LOINC, SNOMED, ICD-10).

The paper's key idea: write a recipe in JSON that anyone can read, audit, and re-run. Example for Ravi's SpO2 feature:

{ "name": "spo2_last_3_hours", "description": "Average SpO2 over each of last 3 one-hour windows", "fhirQuery": "Observation?code=http://loinc.org|2708-6", "temporalAgg": { "lastN": 3, "windowPeriod": "h", "windowSize": 1, "aggOp": ["avg", "min", "max", "stddev"] } }
This recipe travels — Spain, India, Japan can all run it against their own FHIR data and get directly comparable AI training datasets.

The same recipe that built the training dataset now feeds the live prediction — so the model sees Ravi's data in exactly the format it was trained on. That consistency is what makes the prediction trustworthy.

If Ravi were in a Spanish or Dutch hospital running the same recipe, the same model would give a comparable prediction. That's the EU Health Data Space dream.
